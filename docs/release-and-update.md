# Release And Update Runbook

## GitHub Secrets

- `TAURI_SIGNING_PRIVATE_KEY`: contents of the private key generated by `pnpm exec tauri signer generate`.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password used when generating that private key.
- `APPLE_CERTIFICATE`: base64-encoded `.p12` for your `Developer ID Application` certificate. Required only when Apple signing is enabled.
- `APPLE_CERTIFICATE_PASSWORD`: password used when exporting the `.p12`. Required only when Apple signing is enabled.
- `APPLE_API_ISSUER`: App Store Connect issuer id. Required only when Apple signing is enabled.
- `APPLE_API_KEY`: App Store Connect key id. Required only when Apple signing is enabled.
- `APPLE_API_KEY_CONTENT`: raw contents of `AuthKey_<key-id>.p8`. Required only when Apple signing is enabled.

## GitHub Variables

- `ENABLE_APPLE_SIGNING`: set to `true` to enable Apple certificate import, codesigning, and notarization in GitHub Actions.

When `ENABLE_APPLE_SIGNING` is unset or any value other than `true`, both workflows build unsigned macOS bundles and ignore the Apple signing secrets.
When `TAURI_SIGNING_PRIVATE_KEY` is missing, malformed, or its password is missing, both workflows automatically disable updater artifact signing and skip `latest.json`.

You can use `APPLE_ID`, `APPLE_PASSWORD`, and `APPLE_TEAM_ID` instead of the App Store Connect API key variables, but the workflows in this repo are written around `APPLE_API_KEY_CONTENT`.

## Nightly Release Flow

1. Merge a change into `main`.
2. GitHub Actions runs `macos-nightly`.
3. The workflow rebuilds macOS bundles for both Apple Silicon and Intel targets.
4. Assets are uploaded to the `nightly` prerelease on GitHub Releases.

Nightly builds are for QA/distribution only. They do not publish updater metadata for production clients.
When Apple signing is disabled, the uploaded `.app` and `.dmg` are unsigned and may require Gatekeeper bypass on macOS.

## Stable Release Flow

1. Run `pnpm release:version X.Y.Z`.
2. Run `pnpm check`.
3. Commit the version bump.
4. Create tag `vX.Y.Z`.
5. Push the branch and tag.
6. GitHub Actions runs `release-stable`.
7. The workflow uploads macOS bundles to the tagged GitHub Release.
8. If updater signing secrets are valid, the workflow also uploads `latest.json` and updater signatures.

If `ENABLE_APPLE_SIGNING=true`, the stable workflow also signs and notarizes the macOS bundles before upload.
If Apple signing is disabled, the release artifacts are unsigned and may require manual approval to open on macOS.

The application updater reads:

- `https://github.com/cyhndaugust/bs-tools/releases/latest/download/latest.json`

Because `nightly` is a prerelease, it does not replace the stable release used by the updater endpoint.

## Local Key Material

- Private updater key: `~/.tauri/bs-tools-updater.key`
- Private updater key password: `/tmp/bs-tools-updater-key-password.txt`
- Public updater key committed to the repo: `src-tauri/updater-public-key.pem`

Move the private key password into GitHub secret storage before deleting the temporary file.

## Recovery

- If `macos-nightly` fails, fix the workflow input or signing secret and re-run the workflow from GitHub Actions.
- If `release-stable` succeeds without `latest.json`, verify that `TAURI_SIGNING_PRIVATE_KEY` is the raw minisign private key generated by `pnpm exec tauri signer generate` and that `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` matches it.
- If notarization fails with `ENABLE_APPLE_SIGNING=true`, check the Apple certificate and App Store Connect credentials first.
